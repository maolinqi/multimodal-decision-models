# 图二延迟实验：其余五个模型的双卡补测

本轮补测 README 实验二的自然生成与直接决策延迟。已完成的 Gemma-4-26B-A4B-it 和 Gemma-3n-E4B-it 不重复运行；前一轮准确率矩阵并非这次补测目标，其记录独立保留。

## 实验协议

- **目标：** 测量五个基座的自然生成回答与直接候选决策之间的延迟差异。
- **方法：** 相同模型、图像、状态、问题、候选和中性提示；自然生成采用贪心解码到 EOS，直接决策采用一次前向，不生成新文本。没有单字母、额外解释或最小输出长度要求。生成保留 2,048-token 紧急上限，所有短回答及触顶回答都保留。
- **基准：** 与已有 Gemma 3n E4B 行一致的 ScienceQA 固定 100 道带图测试题，seed 42；记录文件及每张图片均通过既有 manifest 哈希检查。
- **测量：** 一次完整实验包含每题三次配对测量，与已有行的重复次数一致。每题先取重复中位数，再汇总全题中位数；记录自然输出长度与加速比例。包含输入准备、同步计算及结果读出，排除模型加载、网络及排队。
- **验证：** 每题额外保存一次原生生成首步 logits 与直接前向的比较，不计入延迟配对。保留原始输出、候选预测、共享输入哈希、截断记录和参数版本检查；不能把首步一致性等同于自然回答准确率一致。
- **结果：** 补测尚未完成，当前只确认两条后台队列已经启动。完成后从各模型 `summary.json` 和完整 `measurements.jsonl` 审核结果，不能从速度单独推断准确率。

MiniCPM 和 InternVL 的原生接口通过 `inputs_embeds` 生成，只返回新增 token；Qwen / Gemma 的原生序列包含输入前缀。评测脚本分别处理，避免误删 MiniCPM / InternVL 的实际回答。
