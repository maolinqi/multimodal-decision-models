# 七个基座的串行准确率实验

本轮针对 README 准确率表保留的两项基准，给七个官方冻结基座安排完整复测。实验已提交后台队列，尚未完成；README 表中的数值仍是历史实测值，不是本轮结果。

- **实验目标：** 在相同固定题目、图像、状态与候选上，测量七个免训练基座的直接决策准确率。
- **比较的方法：** 七个基座均冻结、不加载决策适配器、不生成文字；使用统一中文选择提示与各模型原生多模态模板，单次前向读取候选标签 logits。Decider / Rune 的作者报告仅作参考，本轮不运行其训练权重。
- **测试基准：** Visual7W 固定 300 题，以及 Rune normalized-v6 公开重建集 136 题。每个模型 436 题，七个模型共 3,052 次决策。本轮不安排已从 README 表中删除的 RAVEN 行对应实验；历史数据仍保留。
- **实验结果：** 待完成后读取逐题预测与 summary.json；当前只确认提交和数据预检通过。
- **结果解析规则：** 分别报告两项基准的正确数、总题数、准确率和推理异常数。保留全部错误和异常，不挑选题目或最高分；不能将不同模型的成绩与针对另一基座训练的作者模型视作严格配对比较。原生模板与视觉预算存在模型差异，本轮协议也不能与历史结果无条件混用。

## 顺序和显存规则

按官方权重文件中的总参数元素数排序，未使用 MoE 激活参数量或 Gemma 3n 的有效参数量作为排序依据。

| 顺序 | 模型 | 权重参数元素数（约 B） | 最低可用显存（含 4 GiB 余量） |
|---:|---|---:|---:|
| 1 | Qwen3.5-2B-Base | 2.274 | 12 GiB |
| 2 | Gemma-3n-E2B-it | 5.439 | 20 GiB |
| 3 | Gemma-3n-E4B-it | 7.850 | 24 GiB |
| 4 | InternVL3.5-8B | 8.528 | 26 GiB |
| 5 | MiniCPM-V-4.5 | 8.696 | 26 GiB |
| 6 | InternVL3.5-14B | 15.120 | 38 GiB |
| 7 | Gemma-4-26B-A4B-it | 25.806 | 66 GiB |

同一时刻仅启动一个评测子进程；前一个模型的两项基准结束、进程退出并释放显存后，才启动下一个。每次启动前检查显存，加载前再次检查，并设置进程显存预算。显存不足或 CUDA OOM 时写入 `paused_memory` 并退出队列，不跳过模型、不自动重试。其他加载失败或连续三次推理失败同样暂停，保留日志。显存阈值是准入规则，不保证任意输入都不会触发 OOM。

配置固定记录文件哈希、436 张输入图像哈希、模型配置哈希和适配器源码哈希。模型接收图像、问题、状态、候选，不接收 gold。Gemma 4 使用 280 图像 token；其他视觉配置沿用已验证适配器。每题结果中保存共享提示哈希与图像哈希。

服务器项目目录内的记录：

- `results/status.json`：整个队列状态及当前模型。
- `results/controller.log`、`results/controller.pid`、`results/queue.exit`：调度日志、进程及结束码。
- `results/<model>.log`、`results/<model>.exit`：各模型日志与结束码。
- `results/<model>/protocol.json`、`predictions.jsonl`、`status.json`、`summary.json`：协议、全部逐题预测、进度与完成摘要。
- `results/summary.json`：只有七个模型全部完成才生成的汇总。

暂停后释放足够显存或修复失败原因，再在服务器项目目录执行 `bash start_serial.sh`。调度锁避免重复启动；已完成模型会跳过，当前模型从已保存记录继续。运行中出现 OOM 的那一题仍按异常保留，不被静默删掉。需要重测失败题时，应创建新的明确标注的实验目录，保留本轮原记录。

主动停止时，先从 `results/status.json` 读取 `child_pid`，核对该进程确为本目录的 `evaluate_accuracy_matrix.py --plan .../plan.json`，然后对该子进程发送 SIGTERM；调度器会暂停并记录退出码，不会继续启动其他模型。没有活动子进程时，不需停止其他服务。
