# 基座行为保持：配对验证方法

本评测回答：**在相同基座权重、相同已预处理输入、相同提示与候选集下，决策改造是否改变了原生模型的第一步输出及候选选择？**

它验证已开放多模态决策通路的行为保持，不证明基座全部功能、所有输入或真实任务能力完整保留。

## 对照设计

| 项目 | 基座原生推理 | 改造后的决策推理 |
|---|---|---|
| 权重 | 同一官方基座快照 | 同一快照，不加载决策 LoRA |
| 输入 | 同一已预处理文字、图像与状态 | 同一输入 |
| 提示、候选集合 | 相同 | 相同 |
| 精度、注意力实现 | 相同 | 相同 |
| 执行路径 | 官方 `generate(max_new_tokens=1)` 的原始 logits | 项目决策前向的最后位置 logits |
| 决策读出 | 相同候选标签上的 softmax 与 argmax | 相同候选标签上的 softmax 与 argmax |

原生对照使用 `output_logits=True`，避免将生成器额外的 logits processors 当作模型计算本身。本评测不比较自由文本回答与选项分类之间的准确率，也不宣称验证了多词元生成的一致性。

## 固定探针

[`benchmarks/base_retention_v1.json`](../benchmarks/base_retention_v1.json) 包含 20 个固定文字与合成图像探针。图像直接保存为 base64，每次运行使用相同像素；报告记录完整 suite 文件 SHA256。

| 类别 | 数量 |
|---|---:|
| 文字计算 | 2 |
| 文字语言 | 2 |
| 文字逻辑 | 2 |
| 颜色识别 | 2 |
| 图像计数 | 2 |
| 图像 OCR | 2 |
| 左右位置 | 2 |
| 上下关系 | 2 |
| 双图判断 | 2 |
| 时序变化 | 2 |

这些是小规模行为探针，不是公开基准，不用于跨模型排名。20 个样本也不足以支持统计等价性或普遍“无损”结论。

## 指标

- 完整词表和候选 logits 的最大绝对差，以及有限数值位置是否一致。
- 候选概率最大绝对差、决策一致率。
- 原生对照与决策通路在同一探针上的正确数、各类别正确数。
- 推理前后参数对象和版本计数是否变化；这一检查不替代全部权重内容的逐字节校验。
- 图像探针的视觉 token 数量、总输入 token 数量和实际输入帧数。

第一步 logits 容差为 `1e-3`，所有候选决策须一致，参数对象与版本计数须不变。报告同时保留错误答案；不以正确率筛选或删除样本。

## 复现

```bash
MODEL_ROOT=/path/to/models CUDA_VISIBLE_DEVICES=0 \
  .venv/bin/python scripts/compare_base_retention.py gemma-e2b \
  --out evidence/retention/gemma-e2b.json
```

其余模型 ID 为 `gemma-e4b`、`minicpm-v45`、`internvl35-8b`、`internvl35-14b`。建议逐个运行，避免同时驻留多个大模型。

保存的完整报告含 `status=completed`。`.partial.json` 是尚未完成的中间记录，不得引用为最终验证通过。

## 解释范围

我们的改造保留各基座的原生视觉编码、视觉语言融合与语言模型对象，新增受限候选读出、结构化协议与运行管理。本版本没有训练新参数。

本评测共享项目的图像缩放、切片数量、8192-token 上限和候选提示，因此不检测这些预算约束相对于各基座默认高分辨率配置的影响。当前 API 也不开放音频或原生自由文本生成。

更广泛的“基本能力保留”需要增加真实数据、原生默认配置与项目配置对照、多词元生成和正式多模态基准。当前结果仅支持在已测输入与设置下保持原生第一步计算及候选决策行为。
