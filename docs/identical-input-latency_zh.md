# 改造前后：相同输入的配对延迟实验

两边看到完全相同的图片、状态、问题、选项和提示，共同提示不额外要求只回答一个字母，不要求简短或额外解释；原题文字保持原样。Gemma 两边均使用关闭 thinking 的原生 instruction 模板，本实验不与开启 thinking 的模式比较。原模型正常生成，决策路径直接选择。仅使用官方冻结权重，无额外训练；没有向任何一方提供额外解释要求或信息。Gemma 136 题，每题每条路径测量三次。

|基座|题数|原模型观测响应中位耗时|决策评分中位耗时|相差|加速比及配对 95% 区间|延迟减少|
|---|---:|---:|---:|---:|---:|---:|
| Gemma-4-26B-A4B-it | 136 | 12512.1 ms | 248.2 ms | 12263.9 ms | 50.40× [47.28, 56.37] | 98.0% |

表中先求每题三次测量的中位数，再对题目汇总。置信区间以题目为配对重采样单位，重复测量不冒充更多独立题目；所有测量及 P95 均保留，没有删除延迟异常值。

A800-SXM4-80GB，BF16，SDPA，模型已加载。计时包含图片和文本准备、传输、同步模型计算及结果读取，不包含模型加载、网络和服务排队。原模型采用贪心生成、正常 EOS、2,048 新 token 的异常保护上限（所有触顶均披露，不把截断耗时描述为完整回答耗时）；改造后一次前向、生成 0 新文本 token。两边的初始输入完全相同。旧的单字母提示实验和不同提示解释组均不计入本次比较。

候选决策与原生生成第一步的候选 logits 在 136/136 个同输入检查中保持一致；这不等于任意自由生成答案或全部模型能力都已证明不变。原生生成的实际 token 数、正确率、未解析回答和截断均在[英文详细结果](identical-input-latency.md)与逐题证据中公开。

准确率对照：修正前缀后的 Qwen，RAVEN 59.33%（作者报告 80%）、Visual7W 90.33%（作者 89%）；共同候选位置对应与原始表格单元格输入下的 Gemma 为 68.38%（作者 Rune v3 报告 75.7%，280 图像令牌）。未运行作者训练模型，未核验作者逐题输入完全一致，不能据此宣称非劣效或整体更好。

负面记录也保留：Qwen 旧答案前缀存在 token 边界问题，换行修正版全部 3,600 个候选检查通过。Gemma 标记和说明修正从 55.88% 提高到 67.65%，随后表格截断修复降到 66.18%；最新版共同输入提供位置对应和 455 个原始结构化表格单元格，得分 93/136；这不是自动截图 OCR 的验证。

历史标记版本的 48 张重建截图保留了目标区域像素，但识别检查并非全部通过：同尺寸单标记识别 98.75%，完整截图坐标条件字母识别 79.17%，目标框与字母对应 78.33%。坐标检查包含空间定位和选项匹配，不能把所有失败归因于 OCR；也不能声称外部因素已完全排除。最新版改用原图与同样大小的五个候选裁剪，字母放在裁剪外，并为两边共同提供候选位置对应；不再要求依赖引线或截图字母 OCR。结构化位置对应减少了识别歧义，但不能保证模型正确理解对象与任务。8 张作者示例卡保持原样，未纳入这 48 张像素保护审计。
